# APP-001 — Food basket — актуальный контракт v1.0

> Каноническое ТЗ APP-001. При разработке ориентироваться на этот файл и `main`. Google Drive используется только для DATA/recovery/BACKUP SAFE.

## 1. Назначение

Персональное приложение для домашнего учёта запасов и регулярных закупок.

Основной цикл:

`что есть дома → проверить остатки → сформировать корзину → выбрать магазин → цены/количество → собрать товары → завершить покупку → история`

## 2. Запуск и архитектура

### Канон

- Repository: `https://github.com/setjip-spec/APP-001-Food-basket`
- Live URL: `https://setjip-spec.github.io/APP-001-Food-basket/`
- Канонический код: GitHub `main`.
- Пользовательский runtime/UI: **GitHub Pages only**.
- Google Apps Script Web App больше не является допустимым финальным runtime.
- Google Drive / Sheets допускаются только как DATA/recovery/backup.

### Текущая миграция

На момент принятия этого правила текущий GitHub Pages `index.html` ещё открывает legacy Apps Script через iframe. Это временная несовместимость и следующий инфраструктурный долг APP-001.

APP-001 считается полностью переведённой на новую архитектуру только после удаления Apps Script iframe/runtime и проверки самостоятельной GitHub Pages-версии.

### DATA MODE

Перед финальной миграцией нужно выбрать один режим:

- **LOCAL** — IndexedDB/localStorage + обязательный JSON export/import. Предпочтительный простой режим, если приложение используется на одном устройстве/браузере.
- **CLOUD DATA** — внешний API/облачное хранилище, если нужна синхронизация между устройствами.
- **EXTERNAL BACKEND** — отдельный backend, если нужны секреты, auth, серверная логика, фоновые задачи или интеграции.

Секреты, private tokens и service-account credentials нельзя хранить в публичном frontend GitHub Pages.

## 3. Продукты

Для продукта поддерживаются:

- постоянный `product_id`;
- название;
- категория;
- единица `шт.` или `кг`;
- ручная норма на неделю;
- на сколько дней хватает;
- текущий остаток;
- ориентировочная цена;
- статус дома;
- дата последней покупки/проверки;
- `Почти пусто` для штучных товаров.

Для `шт.` шаг = 1. Для `кг` хранение с точностью 0,1 кг; пользовательский шаг +/- задаётся в настройках.

## 4. Статусы дома

- `закончилось`: остаток = 0;
- `заканчивается`: включено `Почти пусто` или остаток ниже настраиваемого процентного порога от недельной нормы;
- `есть достаточно`: остальные случаи.

`Почти пусто` у штучного товара уменьшает эффективный остаток для расчёта корзины на одну единицу.

## 5. Проверка остатков

Перед формированием корзины открывается быстрый список:

`Продукт | Хватает | Осталось сейчас`

Количество меняется степпером. Для штучных товаров рядом доступна компактная отметка `Почти пусто`.

## 6. Корзина

Корзина является локальным черновиком до явного сохранения.

Пользователь может:

- менять количество +/-;
- вводить цену;
- выбрать один магазин для всей корзины;
- сортировать по алфавиту или категориям;
- отметить товар как `собрано` — строка становится зелёной и уходит вниз;
- удалить товар — он остаётся в отдельном зачёркнутом списке и не возвращается после обычной перезагрузки;
- восстановить удалённый товар вручную;
- добавить существующий товар из `Остальные товары`;
- добавить новый товар.

Удалённый товар автоматически возвращается только после нового явного сценария `Проверить остатки → Сформировать корзину`, если по новым остаткам он снова нужен.

### Сохранить корзину

Кнопка пакетно сохраняет:

- состав;
- количества;
- цены;
- магазин;
- статусы `активно / собрано / удалено`.

Изменение отдельного поля не должно вызывать долгую запись на каждый клик.

## 7. Магазин

В v1.0 один магазин выбирается для всей текущей корзины.

Текущие магазины:

- Самокат;
- Ашан;
- Пятёрочка;
- Магнит.

Отдельный пользовательский экран `Магазины и кэшбэк` не нужен.

## 8. Кэшбэк

Процент и лимит задаются вручную прямо в корзине рядом с магазином.

Формула:

`cashback = min(сумма × процент / 100, лимит)`

Если лимит = 0, ограничение не применяется.

Правила:

- процент и лимит не относятся к кнопке `Сохранить корзину`;
- они являются параметрами текущей покупки;
- на экране сразу пересчитываются `Общая стоимость`, `Экономия кэшбэка`, `После кэшбэка`;
- окончательно фиксируются при `Покупка совершена`.

## 9. Завершение покупки

Окно завершения не просит повторно вводить процент, лимит или фактический кэшбэк.

Оно наследует из корзины:

- магазин;
- процент;
- лимит.

Редактируемые поля:

- фактическая сумма;
- скидка.

Кэшбэк автоматически пересчитывается по фактической сумме и заданному проценту/лимиту.

Если в корзине остались несохранённые изменения, `Покупка совершена` должна сначала сохранить актуальный черновик, затем завершить покупку одной пользовательской операцией.

## 10. История

При завершении сохраняются:

- дата/месяц;
- магазин;
- плановая и фактическая сумма;
- скидка;
- рассчитанный кэшбэк;
- чистые расходы;
- позиции покупки;
- метаданные процента и лимита.

После покупки остатки обновляются, `Почти пусто` для купленных товаров сбрасывается.

## 11. Главная

Верхние карточки:

1. `Нужно докупить`;
2. `В корзине`;
3. `Стоимость`;
4. `Кэшбэк`.

## 12. Категории и сортировка

Категории отображаются как сворачиваемые строки общей таблицы, чтобы сетка колонок не съезжала.

Экран `Продукты` поддерживает:

- по категориям;
- А–Я;
- остаток меньше→больше;
- остаток больше→меньше.

Корзина поддерживает:

- по алфавиту;
- по категориям.

## 13. Настройки

Поддерживаются:

- порог `заканчивается`, %;
- шаг количества для кг;
- видимость колонок `Что дома`;
- режим `алфавит / категории`.

- `main` — канон.

- Небольшие безопасные правки допускаются прямо в `main`.

## 16. Критерий рабочей v1.0

Функциональный сценарий:

`остатки / почти пусто → сформировать корзину → отредактировать → магазин + кэшбэк → сохранить/собрать → завершить покупку → история → повторное открытие`

Инфраструктурный критерий новой архитектуры:

- приложение открывается и работает непосредственно на GitHub Pages;
- нет зависимости от Google Apps Script Web App/iframe;
- DATA MODE зафиксирован и устойчив к перезагрузке;
- есть export/import или cloud recovery для пользовательских данных;
- актуальные ссылки записаны в `docs/LINKS.md` и REGISTRY;
- создан свежий Google BACKUP SAFE snapshot.


## 17. Режим телефона

APP-001 имеет отдельный мобильный рабочий режим для сценариев у холодильника и в магазине. Это не отдельное приложение и не отдельная база: используется тот же Supabase state, что и на компьютере.

### Назначение

На телефоне доступны только два основных сценария:

1. **Остатки** — быстро пройти товары дома, изменить фактическое количество и отметить «Почти пусто».
2. **Корзина** — использовать текущую корзину непосредственно в магазине.

Экран создания и администрирования продуктов на телефоне не нужен. Новые продукты, категории, настройки и прочая справочная работа выполняются с desktop-версии.

### Мобильные остатки

- Остатки редактируются прямо на странице, без необходимости открывать desktop-таблицу.
- Для каждого продукта показываются название, категория, единица, текущий статус и степпер количества.
- Для штучных товаров сохраняется компактная отметка «Почти пусто».
- Цветовые статусы сохраняются: заканчивается — приглушённо-красный, закончилось — ярко-красный.
- Кнопка «Сохранить остатки и собрать корзину» пакетно сохраняет все проверенные остатки и сразу пересчитывает корзину.
- Если корзина имела несохранённый черновик, перед пересборкой он сначала сохраняется, чтобы мобильный сценарий не терял изменения.

### Мобильная корзина

На телефоне можно:

- видеть фактический остаток дома рядом с каждой позицией;
- отмечать товар как «собрано»;
- менять количество покупки + / −;
- менять цену за единицу;
- видеть сумму строки;
- удалять товар из текущей корзины;
- возвращать удалённый товар;
- добавлять в корзину уже существующий товар из раздела «Остальные товары»;
- выбирать магазин;
- вводить процент и лимит кэшбэка;
- сохранять корзину;
- завершать покупку.

На телефоне **нельзя создавать новый продукт** через корзину.

### Навигация

При ширине телефона интерфейс переключается на нижнюю навигацию из двух пунктов:

- «Остатки»
- «Корзина»

Desktop-разделы «Главная», «Продукты», «История», «Настройки» в мобильном рабочем режиме не показываются. Desktop-версия при этом остаётся без изменения своего функционального состава.

### Синхронизация

Телефон и компьютер используют один APP-001 cloud state в Supabase. Сохранённые на телефоне остатки, корзина и завершённые покупки должны быть видны на компьютере после обновления данных и наоборот.
