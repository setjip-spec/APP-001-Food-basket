# APP-001 — Food basket — актуальный контракт v1.0

> Этот файл — каноническая рабочая спецификация APP-001 после перехода на GitHub-first разработку. При разработке ориентироваться на этот файл и код `main`. Google Drive используется как независимый BACKUP SAFE.

## Назначение

Персональное приложение для домашнего учёта продуктовых запасов и регулярных закупок.

Основной цикл:

`что есть дома → проверка остатков → сформировать корзину → выбрать магазин → цены/количество → собрать товары → завершить покупку → история`

## Runtime, запуск и данные

- Пользовательская точка запуска: **GitHub Pages**.
- Целевой URL: `https://setjip-spec.github.io/APP-001-Food-basket/`.
- GitHub Pages в v1.0 работает как полноэкранный launcher рабочего Apps Script Web App.
- Backend/runtime: **Google Apps Script Web App**.
- Backend данных: **Google Sheets**.
- GitHub — канонический источник ТЗ и исходного кода.
- `main` — версия, предназначенная для публикации/синхронизации runtime.
- Google Drive `03 MINI APPS — BACKUP SAFE` — аварийный резерв, а не рабочее место разработки.

Архитектура v1.0:

`GitHub main → GitHub Pages → Apps Script Web App → Google Sheets DATA`

## Продукты

Для каждого продукта поддерживаются:

- постоянный `product_id`;
- название;
- категория;
- единица учёта `шт.` или `кг`;
- ручная норма на неделю;
- на сколько дней хватает;
- текущий остаток;
- ориентировочная цена;
- статус дома;
- дата последней покупки/проверки;
- отметка `Почти пусто` для штучных товаров.

Для `шт.` шаг количества = 1. Для `кг` данные хранятся с точностью 0,1 кг; пользовательский шаг +/- выбирается в настройках.

## Статусы дома

- `закончилось`: остаток = 0;
- `заканчивается`: включено `Почти пусто` или остаток ниже настраиваемого процентного порога от недельной нормы;
- `есть достаточно`: остальные случаи.

`Почти пусто` у штучного товара уменьшает эффективный остаток для расчёта корзины на одну единицу.

## Проверка остатков

Перед формированием корзины открывается быстрый список:

`Продукт | Хватает | Осталось сейчас`

Количество меняется степпером. Для штучных товаров рядом доступна компактная отметка `Почти пусто`.

## Корзина

Корзина является локальным черновиком до явного сохранения.

Пользователь может:

- менять количество +/-;
- вводить цену;
- выбрать один магазин для всей корзины;
- сортировать по алфавиту или категориям;
- отметить товар как `собрано` — строка становится зелёной и уходит вниз;
- удалить товар — он остаётся в отдельном зачёркнутом списке и не возвращается после перезагрузки;
- восстановить удалённый товар вручную;
- добавить существующий товар из списка `Остальные товары`;
- добавить новый товар.

Удалённый товар автоматически может вернуться только после нового явного сценария `Проверить остатки → Сформировать корзину`, если по новым остаткам он снова нужен.

### Сохранение корзины

`Сохранить корзину` пакетно сохраняет:

- состав;
- количества;
- цены;
- магазин;
- статусы `активно / собрано / удалено`.

Изменение каждого отдельного поля не должно вызывать серверную запись.

## Магазин

В v1.0 один магазин выбирается для всей текущей корзины. Backend-справочник магазинов сохраняется, отдельный пользовательский экран `Магазины и кэшбэк` не используется.

## Кэшбэк

Процент и лимит кэшбэка задаются вручную прямо в корзине рядом с магазином.

Формула:

`cashback = min(сумма × процент / 100, лимит)`

Если лимит = 0, ограничение не применяется.

Важно:

- процент и лимит не являются частью операции `Сохранить корзину`;
- они живут как локальные параметры текущей покупки;
- на экране мгновенно показываются `Общая стоимость`, `Экономия кэшбэка`, `После кэшбэка`;
- окончательно параметры кэшбэка фиксируются при `Покупка совершена`.

## Завершение покупки

Окно завершения не просит повторно вводить процент, лимит или фактический кэшбэк.

Оно наследует из корзины:

- магазин;
- процент;
- лимит.

Редактируемые поля:

- фактическая сумма;
- скидка.

Кэшбэк автоматически пересчитывается по фактической сумме и заданным в корзине проценту/лимиту.

Если в корзине остались несохранённые изменения, `Покупка совершена` должна сначала сохранить актуальный черновик, затем завершить покупку одной пользовательской операцией.

## История

При завершении сохраняются:

- дата/месяц;
- магазин;
- плановая и фактическая сумма;
- скидка;
- рассчитанный кэшбэк;
- чистые расходы;
- позиции покупки;
- метаданные процента и лимита кэшбэка.

После покупки остатки продуктов обновляются, `Почти пусто` для купленных товаров сбрасывается.

## Главная

Верхние карточки v1.0:

1. `Нужно докупить`;
2. `В корзине`;
3. `Стоимость`;
4. `Кэшбэк`.

Карточки используют актуальное состояние/локальный черновик там, где это возможно.

## Категории и сортировка

Категории берутся из справочника Google Sheets. На экранах с группировкой категории отображаются как сворачиваемые строки одной общей таблицы, чтобы сетка колонок не съезжала.

Экран `Продукты` поддерживает сортировку:

- по категориям;
- А–Я;
- по остатку меньше→больше;
- по остатку больше→меньше.

## Настройки

Поддерживаются:

- порог `заканчивается`, %;
- шаг количества для кг;
- видимость колонок экрана `Что дома`;
- режим `алфавит / категории`.

## GitHub workflow

- Репозиторий: `setjip-spec/APP-001-Food-basket`.
- Канон: `main`.
- Apps Script backend разделён на `src/01_Server.gs` … `src/09_Server.gs`.
- Apps Script UI разделён на `src/Index.html`, `Body*.html`, `Style*.html`, `Script*.html`.
- Корневой `index.html` — GitHub Pages launcher.
- `.nojekyll` — прямой static publish Pages.
- Значимые изменения: ветка → проверка → pull request → `main`.
- Правка, сделанная только в Apps Script Editor и не возвращённая в GitHub, считается незавершённой.

### Первичная настройка GitHub Pages

Один раз:

`Repository → Settings → Pages → Deploy from a branch → main → /(root) → Save`.

После публикации основной пользовательский URL должен быть:

`https://setjip-spec.github.io/APP-001-Food-basket/`

### Backend sync

До настройки автоматической доставки backend изменения из GitHub требуется синхронизировать с существующим Apps Script-проектом отдельно. Целевое состояние — `clasp`/GitHub Actions, чтобы backend также обновлялся из GitHub без ручного копирования.

## Google BACKUP SAFE

Для milestone/stable версии создаётся независимый Google Drive snapshot.

Минимум snapshot:

- копия Google Sheets DATA;
- копия ТЗ;
- резерв исходников/ключевых исходников;
- BACKUP MANIFEST с GitHub URL, live URL, версией и датой.

Порядок восстановления: сначала Git history/revert, затем Google BACKUP SAFE.

## Критерий рабочей v1.0

Полный сценарий должен проходить без потери данных:

`остатки / почти пусто → сформировать корзину → отредактировать → магазин + кэшбэк → сохранить/собрать → завершить покупку → история → повторное открытие`.
