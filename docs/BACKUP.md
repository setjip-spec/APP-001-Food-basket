## Зачем нужен Google backup

Он должен позволить восстановить APP-001 даже если:

- удалён GitHub-репозиторий;
- потерян доступ к GitHub-аккаунту;
- main испорчен ошибочным изменением;
- нужно восстановить старую stable-версию;
- потеряна или повреждена рабочая DATA;
- нужно быстро пересоздать репозиторий под тем же APP-ID.

## Когда делать snapshot

Обязательно:

- stable/milestone release;
- перед крупной миграцией архитектуры;
- перед destructive DATA-изменением;
- перед сменой DATA MODE;
- после аварийного восстановления;
- по прямой просьбе пользователя.

Не обязательно делать Google snapshot после каждой мелкой правки: для этого существует Git history.

## Что хранить

Минимальный recovery-набор:

1. актуальное ТЗ;
2. исходники или source bundle/копия ключевых файлов, достаточная для пересоздания GitHub repo;
3. DATA snapshot, если у приложения есть отдельные пользовательские данные;
4. `BACKUP MANIFEST`: APP-ID, версия, дата, repository URL, live URL, DATA URL и порядок восстановления.

## Восстановление

1. Сначала использовать Git history / revert / предыдущий commit.
2. Если GitHub недоступен или репозиторий утрачен — создать новый repo с тем же APP-ID.
3. Восстановить ТЗ и исходники из Google BACKUP SAFE.
4. Включить GitHub Pages.
5. Восстановить DATA только после проверки даты snapshot.
6. Проверить основной пользовательский сценарий.
7. Записать актуальные ссылки в `docs/LINKS.md` и общий REGISTRY.
8. Создать новый snapshot после восстановления.
